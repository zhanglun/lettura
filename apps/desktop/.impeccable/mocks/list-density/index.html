Lettura 0.2.x · 列表时间分组重设计

稀疏的一天，不该看起来像坏掉的应用

现状：今天没同步时，首屏 = 3 行内容 + 4 条「已收起」横幅 + 一片空白。折叠机制本是为 27k 未读的秩序而设，但它的视觉形态让「没有新东西的一天」读作「没有东西」。以下两个方案同保现役行词汇与「静密 × 聚光」世界不变，只重构「时间分组」这一层的表达。卡片内为静态缩略；点「打开完整稿」进入可交互演示（可滚动 / 可点击分组与档案线 / 标尺跳转 / 切夜读与「今天有数据」场景）。

现状诊断（对应 10-10 截图）

  1. 1死横幅叠屏4 条「已收起」横幅吃掉 ~180px 高度，信息量为零；下方再坠一片空白，首屏内容占比不足 1/3。
  2. 2机制语言外露「已收起 · N 篇」在描述界面自己的折叠状态，×4 重复——违反「界面消失，内容即界面」。
  3. 3计数无行动力「13,110」不帮你做任何决定，却各占一整行；数字与解锁它的动作隔着一整条横幅。
  4. 4时间双重编码组头已说「昨天」，行内又用相对时间说三遍「1 天前」——组内精度本可更高（今天→时刻、本周→周几）。
  5. 5分组头过重色带 + 通栏规则线 + chevron + 大写标签，四重信号压在一个「耳语级」的结构事实上。
方案 A · 修缮

修缮 — 展开照旧，收起去机制文案，时间去重

展开的桶照旧是时间流（默认展开到首屏约 55%，稀疏日自动续借下一桶，首屏是内容不是成排收起头）；收起/展开同一分组头本体——收起态 chevron 转向表达状态，去掉「已收起 · N 篇」机制文案。另修桶内时间格式：组内不再重复相对时间。

打开完整稿 ↗
得稀疏日首屏是满的内容；「已收起」×4 的机制语言清零；行内时间精确化（不再与组头重复）；状态由 chevron 转向表达，结构感与旧版一致。
代价「默认只展开第一个非空桶」升级为「展开到首屏约 55%」——比既有决定更激进一档，但仍是内容优先的同方向延伸；多桶展开时 j/k 序列跨桶，沿用现有可见序列语义（已有机制）。
改动量：≈ 1 天 · 只动默认展开规则与时间格式 · 风险低
方案 B · 重构

时间标尺 — 标尺即地图，流不再折叠

时间不再以横幅插进内容流。六桶概览升格为过滤条下的一把常驻刻度尺（段宽 ∝ 对数计数，队列形状一眼可读；滚动实时追踪所在桶，点击平滑跳转）。列表成为不折叠的连续流，桶界退化为 28px 耳语刻度（标签 + 细线，无色带无 chevron）。

打开完整稿 ↗
得27k 队列的体量与形状第一次有了仪表（本周 vs 更早的比例可读）；无折叠 = 无死横幅，滚动即时间轴；跳转任意桶一键直达；标尺双值随主题，夜读同构。
代价+36px 常驻 chrome（与「界面消失」相逆）；废除「折叠」这一已拍板机制，重开既定决策；跨桶连续流要求重写懒加载通道合并、j/k 焦点序列、滚动恢复与「队列身份」契约；标尺在窄窗口（源棱镜激活）需要响应式降级。
改动量：≈ 3-5 天 · 动 DayHead / 分页 / 键盘契约 · 风险中高

推荐：A（修缮）。B 的标尺确实更「仪器」，但它把概览常驻为家具——每一天都为「只有 3 行内容」的日子付 36px 的税，与「界面消失」相逆；且废除折叠重开了你 9-30 刚拍板的决策。A 走纯减法：默认展开补足首屏、文案去机制化、时间去重，改动面小一个数量级。若日后想要队列全景，分组头可平滑演进为标尺（B），不堵死。
共享修正（两案都包含）：① 桶内时间精确化——今天→「09:41」、昨天→「昨天 21:14」、本周→「周六 09:30」、上周/30 天内→「9月28日」、更早→「2025/12/30」，替换相对时间的三重重复；② 稀疏日自动续借（A）/ 连续流（B）让首屏永远是内容。两稿均已实现可交互演示。
